# lubrAIn 기업 홈페이지

lubrAIn의 Agentic AI 핵심 기술, 컨설팅, CS 대응 솔루션을 소개하는 한국어 기업 사이트와 문의 접수 API입니다. 2026-11-03 사용자가 회사명과 회사 중심 구조를 확정했습니다.

## 실행

Node.js 22.13 이상이 필요합니다.

```powershell
npm ci
npm start
```

`npm start`는 현재 소스를 다시 빌드한 뒤 `http://127.0.0.1:8787`에서 실행합니다. 기존 서버가 켜져 있다면 먼저 종료한 뒤 다시 실행하세요. D1을 쓰는 로컬 문의 테스트에는 `drizzle` 폴더의 모든 SQL 마이그레이션을 번호 순서대로 한 번씩 로컬 데이터베이스에 적용해야 합니다. `0001`은 알림 결과 보고를 검증하는 토큰 해시 열을 추가합니다. 배포 시에는 Sites가 추적된 마이그레이션을 적용합니다.

## 문의 처리

- `POST /api/inquiries`: 입력 길이, 이메일, 개인정보 동의, 제출 시간, 숨은 필드, 링크 수, 동일 이메일의 최근 접수량을 서버에서 확인합니다.
- 접수 내용은 Cloudflare D1의 `inquiries` 테이블에 저장합니다. 동일한 `requestId`는 중복 저장하지 않습니다.
- 운영 문의 알림은 FormSubmit을 통해 `cs.lubrain@gmail.com`으로 전달합니다. 이름, 회사, 문의자 이메일, 문의 분야, 추가 입력 항목과 문의 내용, 접수 ID를 포함합니다. 메일에 답장하면 문의자 주소로 연결됩니다.
- 메일 설정이 없으면 `not_configured`, 브라우저 전달 전에는 `awaiting_browser`, 성공 응답을 브라우저가 보고하면 `browser_accepted`, 실패 보고는 `browser_failed`, 수신 주소 인증이 필요하면 `activation_pending`을 기록합니다. 건별 비밀 토큰의 해시를 DB에 저장해 다른 접수 건의 결과를 바꾸지 못하게 합니다. 브라우저 보고는 메일 서비스의 서명된 배달 확인이 아닙니다. 서버 전송 방식에서는 처리 중 `pending`, 요청 수락 시 `submitted`, 실패 시 `failed` 또는 `failed_http_429` 등 원인 코드를 기록합니다. `submitted`는 메일 서비스의 요청 수락이며 Gmail 받은편지함 도착을 보장하는 상태는 아닙니다. 기존 기록의 `sent`도 이전 코드가 서비스 응답을 확인한 상태입니다.
- 이메일 전송 실패 시에도 저장된 접수 건은 사라지지 않습니다. 운영자는 Sites의 D1 테이블 조회 기능에서 `notification_status`를 확인해야 합니다.

### 운영에 필요한 외부 설정

1. Sites 운영 환경 변수에 `INQUIRY_EMAIL_PROVIDER=formsubmit-browser`, `INQUIRY_TO_EMAIL=cs.lubrain@gmail.com`을 설정합니다. 이 방식은 API 키와 별도 발신 도메인이 필요하지 않습니다.
2. 첫 제출 시 FormSubmit이 보낸 인증 메일의 `Activate Form` 링크를 수신함 소유자가 눌러야 합니다. 수신 주소나 사이트 주소가 달라지면 인증을 다시 요구할 수 있습니다. 인증 여부는 실제 요청 응답과 수신함으로 확인합니다.
3. 환경 변수를 바꾼 뒤 저장된 버전을 다시 배포합니다. 실제 고객 정보 대신 명시적인 시험 문의로 D1 저장, `browser_accepted` 상태와 수신함 도착을 확인합니다. 브라우저에서 전달에 실패하면 같은 접수 건의 알림만 다시 보내는 버튼을 표시합니다. 페이지를 닫거나 전송 요청이 중단되면 자동 재전송하지 않으므로 미완료 건은 저장된 원문을 확인해 별도로 처리해야 합니다.
4. 현재 사이트는 공개입니다. 홈페이지 서버가 입력 검증·스팸 제한·개인정보 동의·DB 저장을 완료한 후, 브라우저가 FormSubmit의 공식 AJAX API로 알림을 전달합니다. 배포 서버에서 직접 보내면 서비스의 429 제한이 발생해 이 방식으로 전환했습니다. FormSubmit에 전달되는 내용과 서비스의 개인정보 안내를 문의 양식에 표시합니다.

향후 발신 도메인을 보유하면 `INQUIRY_EMAIL_PROVIDER=resend`, `RESEND_API_KEY`(비밀값), `INQUIRY_FROM_EMAIL`(인증된 도메인의 발신 주소)을 설정해 Resend로 전환할 수 있습니다. 수신 주소는 그대로 사용할 수 있습니다. 전송 서비스를 바꾸면 문의 양식의 서비스 안내도 맞춰 수정하세요. 비밀키는 소스나 채팅에 넣지 않고 Sites의 비밀값 설정으로 등록합니다.

로컬 사본에는 자동으로 실제 메일을 보내는 설정을 넣지 않았습니다. 로컬 테스트에서 메일 발송이 필요한 경우 Wrangler 설정 파일과 같은 폴더의 `.dev.vars`에 위 두 운영 변수 값을 설정해야 합니다. 현재 실행 설정은 `dist/server/wrangler.json`이며 이 폴더는 다시 빌드할 때 교체되므로, 로컬 메일 테스트용 설정은 빌드 후 적용하고 Wrangler를 직접 실행하세요.

메일 응답 처리 검사: `node scripts/verify-notifications.mjs`. 이 검사는 외부 메일을 보내지 않습니다.

브라우저 전달 API 검사: `node scripts/verify-browser-delivery.mjs <사이트 주소> <수신 주소>`. 시험 문의 한 건을 저장하고 알림 성공·실패 보고를 시뮬레이션합니다. 외부 메일은 보내지 않습니다. 2026-11-03 공개 사이트에서 실제 문의 양식 전송, DB 저장과 사용자의 Gmail 테스트 메일 수신 확인까지 완료했습니다.

## 개인정보 운영

폼의 수집·이용 안내는 문의 응대 목적을 설명합니다. 실제 공개 전에는 회사의 법적 상호, 개인정보 처리 책임자와 연락 경로, 보유 기간, 삭제 절차, 처리 방침을 확정해야 합니다. 수집된 문의에는 고객 원본 로그·비밀키를 넣지 않도록 UI에서 안내합니다. 삭제 요청이나 보유 기간 만료 시 운영자가 D1에서 해당 레코드를 삭제해야 합니다.

## 콘텐츠 근거

핵심 경쟁력은 Agentic AI Workflow 기술과 이를 뒷받침하는 네 가지 역량입니다. 네 역량은 AI 모델·지시 선택, 업무에 필요한 정보 연결, 승인·중단·복구를 포함한 실행 통제, 확인된 해결 절차의 재사용입니다. 이 구조는 `Agentic_AI_핵심경쟁력_4대역량.md`, `GTM_proposal_ITCS_1page_v1_2026-10-30.md`, `ITCS_신규사업전략_v2_2026-10-30.md`를 바탕으로 정리했습니다. 화면에는 전문 용어를 바로 쓰는 대신 고객 업무와 lubrAIn 기술의 적용 방식을 설명합니다.

제품이 개발 완료되었다는 전제는 2026-11-02 사용자의 명시적 지시에 따른 것입니다. 세 활용 사례는 설명용 가상 시나리오이며 실제 고객 성과를 뜻하지 않습니다. 성능 수치와 고객 로고는 넣지 않았습니다.

솔루션 페이지의 웹훅 장애 화면도 시연용 가상 데이터입니다. 문의 접수부터 조사, 원인 재현, 격리된 작업 공간의 수정안·검토용 PR까지 자동으로 이어지고, 관리자가 PR을 한 번 승인한 뒤 고객이 허용한 배포 절차, 해결 확인, 승인된 정책에 따른 고객 안내로 이어지는 예시입니다. 실제 연동·배포·발송 권한과 지원 범위는 고객 환경에서 확인해야 합니다.
